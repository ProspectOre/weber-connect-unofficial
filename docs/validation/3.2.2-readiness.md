# 3.2.2 stable: read-only cloud hotfix

This candidate starts from stable 3.2.1. Only the cloud send boundary and version
manifest change inside the shipped integration. Pairing, controller families,
entities, dependencies and recovery behavior retain the stable implementation.
The broader beta continues separately as 3.3.0 prereleases.

## Change and source proof

Remove both implicit `0x09` device-settings timestamp writes and the unused
`0x0B` program-details request. Permit only exact-integer `0x05`, `0x07`, `0x0E`
commands with empty byte payloads, rejecting everything else before I/O.
Preserve the six remaining startup reads, their pacing, polling and recovery.

Tests cover cold startup, normal polling, same-socket renewal, token rotation,
failed initialization and malformed outbound arguments. Only the socket and
manifest may differ from the stable baseline inside `custom_components`.
The normalized runtime fingerprint excludes only the manifest version label.

## Release gates

The automated and physical receipts bind this exact runtime. All existing stable
physical gates and the one-hour endurance gate remain required. The RC6 trial
used a different runtime and does not authorize this stable release.

- Verify installed files, loaded version, unchanged entry/entity identities and
  the rollback archive before recording live results.
- Verify current probe readings with the official app closed after startup,
  sustained-loss clearing and automatic recovery after owner-controlled power
  cycling, including the actual occupied probe slot.
- Exercise same-hub reauthentication success and cancellation, preserving the
  original entry, devices, entity identities and options.
- Check desktop/mobile settings and activity filtering, then official-app
  coexistence. Keep rendered inspection separate from owner confirmation.
- Run at least 3,600 seconds of continuous ten-second sampling, with no new
  failed updates, manual recoveries, unexpected reloads, capture errors or
  disconnected samples. Update gaps and sampled ages must remain within
  30 seconds. Record the exact sample count, interval and runtime fingerprint.
- Pass exact-head CI and canonical regular review, resolve findings, and merge
  through the platform before publishing stable 3.2.2 and requesting HACS review.

The physical receipt governs runtime evidence; completing it does not waive the
exact-head CI and canonical-review gates below.
