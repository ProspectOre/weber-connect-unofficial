# 3.2.2rc6: read-only cloud candidate

RC6 addresses the [HACS review](https://github.com/hacs/default/pull/9979#pullrequestreview-5567451603)
and retains RC5's fuel freshness and cloud-status fixes. This candidate is not
published yet. Stable 3.2.1 remains the rollback release; its cloud initialization
still contains the settings writes identified by the reviewer.

## Corrected contract

- Remove both `0x09` device-settings frames, including their timestamp payloads.
- Remove the `0x0B` program-details request; its response has no runtime consumer.
- Permit only empty-payload `0x05` status, `0x07` appliance-status and `0x0E`
  capability requests at the session's send boundary. Reject invalid Python
  types, unsupported opcodes and nonempty payloads before any connection/wake I/O.
- Preserve the remaining read sequence, pacing, polling and recovery policy.
- Do not claim that tag `0x15` is safe clock synchronization or that a partial
  settings write preserves omitted settings; neither is needed by this fix.

## Automated proof

The adjacent automated receipt binds results to the runtime fingerprint.
Regression tests enforce outbound types and payloads across cold startup,
normal polling, token rotation, initial connect/send/receive failures,
established disconnects, timeouts and failed recovery. Rejection tests cover
all non-allowed byte opcodes, integer truncation aliases and malformed arguments.
Mocks establish what Home Assistant sends; they do not establish hub behavior.

## Hardware proof and release sequence

1. Pass exact-head CI and regular review, merge, and publish the RC6 prerelease.
2. Install that archive through HACS, restart Home Assistant, verify the loaded
   version and installed runtime fingerprint, and retain a rollback archive.
3. With the official app fully closed, verify current probe readings on cold
   startup and sustained polling. Record model, firmware, sample freshness and
   errors without credentials, identifiers or raw packets.
4. Verify reconnect recovery and new telemetry. Distinguish a controlled socket
   reconnect from actual token expiry, network outage or physical power cycling.
5. Verify official-app coexistence separately; do not let the app silently
   supply a possible setup dependency during the app-closed trial.
6. Attach the exact evidence and remaining limits to the HACS re-review request.
   Stable promotion still requires the repository's full physical matrix.

No prior physical result is transferred to this runtime. Other product-family
qualification remains as recorded in the [product matrix](../product-compatibility.md).
