# 3.3.0rc14 hardware trial build

The RC13 reporter tested EP-series WiFi Thermometer SKU 4553721, firmware
1.4.5_200, on Home Assistant 2026.11.3. Pairing approval succeeded, then setup
timed out on local USB and two ESPHome proxy trials. The reporter saw a short `0xF2` greeting response in the USB log.
The proxy support report mislabeled the connected path as local and used the USB
adapter RSSI. [RC13 report](https://github.com/ProspectOre/weber-connect-unofficial/issues/59#issuecomment-7203938877)

RC14 treats a short or framed plaintext greeting acknowledgement after this
attempt's physical approval as a prompt to request encrypted capabilities. The
acknowledgement does not authenticate the session. Setup advances only after
the capability response authenticates with the newly confirmed key, then verifies
that Weber Cloud associates the exact appliance with the new companion. The
optional STATUS characteristic is subscribed for greeting replies. Connection
diagnostics use the scanner selected by the connected client and its matching
advertisement.

The connected Samsung SM-X210 has Weber Connect 2.13.0.2704 installed and open.
This verifies the OEM app environment only. No EP pairing, cloud association, or
live telemetry trial was performed on the tablet.

## Verification

The synthetic regression fixtures cover bare STATUS acknowledgement and framed
plaintext RESPONSE acknowledgement, followed by an authenticated capability
reply. They also verify unauthenticated and tampered capability responses fail.
Hardware pairing, cloud association, and live readings on RC14 remain pending.
See the [automated receipt](3.3.0rc14-rc-automated.json) and
[hardware receipt](3.3.0rc14-rc-physical.json). Historical hardware and RC13
context remain in the [RC13 readiness record](3.3.0rc13-readiness.md).
