# 3.3.0rc3: read-only probe targets

This unpublished candidate extends the controller-family beta with active probe
target temperatures and target ranges. It also preserves modern zero-valued
plan, step and prompt IDs instead of replacing them with legacy fields.

Cloud traffic retains the empty status/capability reads (`0x05`, `0x07`, `0x0E`)
and adds only a validated `0x0B` probe-program read with a two-byte selector.
It sends no settings, target changes, ignition or cooking-program writes.

Program decoding is based on the installed OEM Android app 2.13.0.2704; see the
[source comparison](2026-11-10-oem-comparison.md). Responses match the pending read window and embedded probe/program/plan,
with pending data reset on session changes. Controller response sequences are
independent of the request; the payload does not echo a session ID. Only the current step
supplies a target, using both exit criteria and prompt triggers. Ranges use two sensors; absent or ambiguous targets stay
unknown. An ambiguous controller error keeps normal recovery behavior and suspends
optional reads until the integration is reloaded. Diagnostics expose that state. Cache age,
session transitions and reconnects prevent indefinite reuse of old targets.

New [automated](3.3.0rc3-rc-automated.json) and
[physical](3.3.0rc3-rc-physical.json) records must bind the exact runtime.
Historical RC2 and earlier receipts do not qualify this candidate. The
[product matrix](../product-compatibility.md) preserves the other controller
issues and per-device gates.

The [targeted live trial](3.3.0rc3-probe-target-observation.json) covers the
existing Connect Hub and Samsung tablet. A 120°F target matched in HA, and direct
range captures established the prompt encoding. Target edits and repeated
program reads remain unreliable, so target delivery is not yet qualified. Full stable
promotion still requires the repository's physical matrix and endurance gates,
plus exact-head CI and review. No other grill is qualified by this Hub trial.
