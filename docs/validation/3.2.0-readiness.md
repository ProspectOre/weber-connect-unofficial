# 3.2.0 release readiness

Status: **not approved for release**. Assessed September 5, 2026.

## Candidate and scope

The working candidate is based on `dc1466bc6346a526784243663ba10f54f0ce76e5`.
Its 23-file integration tree has SHA-256
`a00c46ef0c5eb3c7f82d0d6fb053579806ed531d17bb0d614df34a5af274c347`.
This digest hashes sorted relative paths followed by a NUL and each file's
SHA-256 bytes, excluding Python caches and `.DS_Store`. A runtime change
invalidates the candidate-specific results below.

The intended release includes clearer reading states, same-entry credential
recovery, simpler setup and probe naming, authenticated cloud-only runtime,
bounded dropped-socket recovery, and more useful connection diagnostics.
Activity timestamp noise is addressed through a documented, targeted Home
Assistant logbook exclusion. It is a configuration change, not an automatic
integration migration; upgrades must not silently rewrite user YAML.

## Baseline observation, not candidate acceptance

September 5 observations on Home Assistant Yellow, Home Assistant 2026.9.0,
and a Weber Connect Hub running firmware 2.0.3_7398 used the preceding runtime.
They showed four probe slots, live probe readings, battery and Wi-Fi telemetry,
and working pairing after a Home Assistant restart. With phone Bluetooth off,
the user confirmed that both the Weber app and Home Assistant remained live.

One gap lasted from 18:15:31 to 18:20:19 Pacific. The integration was manually
reloaded at 18:19:10. A later reconnect indication at 18:22:30 cleared at
18:22:32. These events do not establish causation or prove that the candidate
fixes the longer interruption. The previous error text omitted the exception
type, leaving its cause unresolved.
