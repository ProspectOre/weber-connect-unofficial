# 3.3.0rc13 hardware trial build

## EP-series WiFi Thermometer

On SKU 4553721, firmware 1.4.5_200, RC12 kept the link open and the reporter
confirmed the prompt on the display. The USB trace showed request counter 1 and
a notification with appliance counter 28 and boot count 2. RC12 required the
counter to match and timed out on a complete synthetic response with that header.
The reporter also saw a timeout via ESPHome. [RC12 trial](https://github.com/ProspectOre/weber-connect-unofficial/issues/59#issuecomment-7190444970)

The OEM app's MessageProcessor associates the pairing reply with the pending
request class. RC13 matches replies to the expected message type and verifies
the encrypted handshake and capabilities. Setup still requires cloud association
with the exact appliance. The trace header declares 83 body bytes, or 90 bytes
including the header. The report leaves the total notification length ambiguous.
Like the OEM app, RC13 reads the characteristic when an empty or truncated
notification signals a long read. A nonempty prefix must match the complete read.

The connected Samsung SM-X210 ran Weber Connect 2.13.0.2704. Its installed APK
matched the inspected copy (SHA-256
`7642614468495b2d2c7b1d74e708a25633e5b5a7c755defca96c8d05f57a23ab`).
The app showed a Connect Hub offline with Bluetooth enabled. The EP thermometer
still needs an RC13 pairing, cloud-association and live-telemetry trial.

## SmokeFire EX4 Gen 2

During a cook on RC1, fuel changed from full to unknown 81 times. The last
attached diagnostic counted 332 fuel reports, all full. The previous runtime
also expired fuel 60 seconds after its last report while the same connection
was receiving cook telemetry. The regression reproduces that expiry on RC12.
RC13 retains each reported fuel field on that connection and applies explicit
changes immediately. Only values inherited across a reconnect expire at 60
seconds from their original sample. [SmokeFire trial and diagnostics](https://github.com/ProspectOre/weber-connect-unofficial/pull/71#issuecomment-7201246573)

The three diagnostics bracket connection gaps. None captures the approximately
51-minute false idle interval. The OEM app constructs cook mode and target
from each cook-status message, so an omitted field alone cannot establish
that a previous setting still applies. The false idle, healthy-connection
cloud-status flicker and cause of the eight connection gaps remain unresolved.
